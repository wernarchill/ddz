# 斗地主 · 局域网联机版（Android）

一个**标准三人斗地主**的 Android 客户端，支持**局域网联机**：一名玩家当房主，另外两名玩家加入。
纯 Kotlin + 原生 Canvas 自绘，**零第三方依赖**（只用 Android 框架 + Kotlin 标准库）。

### 验证情况

由于无法编译运行，本项目采用**多轮独立静态审查**作为验证手段：
**三轮**审查（编译一致性 → 联机流程/状态机 → 对前两轮修复的复核）
共发现并修复了 **30 余处真实缺陷**，其中值得单独点名的有：

- 一个会让人「打出手里没有的牌 / 跳过一家 / 三家不同步」的**线程模型致命缺陷**

- 若干会让人卡死、失联、误踢的时序缺陷（加入房间收不到回执、一座两连、心跳误踢、

## 如何构建

### 方式 A：云端构建 —— 本机什么都不用装（推荐给当前这台机器）

本机既没有 JDK/SDK，命令行又是坏的，那就把构建搬到云端：

1. 新建一个 GitHub 仓库，把本工程整个文件夹推上去。
2. 打开仓库页面 → **Actions** 标签 → 左侧选 **Build APK** → 右侧 **Run workflow**。
3. 等 3~6 分钟，构建完成后在该次运行页面底部的 **Artifacts** 里下载 `ddz-apk.zip`。
4. 解压得到 `app-debug.apk` / `app-release.apk`，拷到手机点击安装（需允许「安装未知来源应用」）。

工作流在 [.github/workflows/build-apk.yml](.github/workflows/build-apk.yml)：它会装 JDK 17 + Android SDK 34 +
Gradle 8.7，跑一遍规则引擎自测，然后打 debug 与 release 两个包。
`push` 到 `main`/`master` 也会自动触发。

> 为什么这条路能绕开本机的两个障碍：CI 上不依赖 `gradlew`（直接装 Gradle，因为本工程没有提交
> `gradle-wrapper.jar` 这个二进制文件），也不依赖你本机的命令行。

### 方式 B：Android Studio（本机装好环境时最省事）

1. 安装 [Android Studio](https://developer.android.com/studio)（自带 JDK 与 SDK 管理器）。
2. `File → Open`，选择本项目根目录。
3. 首次打开会自动下载 AGP 与 Kotlin 插件（需要联网，约几分钟）。
4. `Build → Build Bundle(s) / APK(s) → Build APK(s)`。
5. 产物在 `app/build/outputs/apk/debug/app-debug.apk`，拷到手机点击安装即可。

### 方式 C：命令行

```powershell
# 1) 确认 JDK 17+
java -version

# 2) 设置 Android SDK（二选一）
setx ANDROID_HOME "C:\Users\你的用户名\AppData\Local\Android\Sdk"
# 或者：复制 local.properties.example 为 local.properties，改里面的 sdk.dir

# 3) 一键构建
pwsh -File .\build-apk.ps1              # release（用 debug 签名，可直接安装）
pwsh -File .\build-apk.ps1 -Debug       # debug
```

`build-apk.ps1` 会自动检查 JDK/SDK、生成 `local.properties`、调用 Gradle，并打印 APK 路径。

**缺失的组件与补装命令：**

```powershell
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
```

**关于 gradlew：** 项目里给了 `gradle/wrapper/gradle-wrapper.properties`，但
`gradle-wrapper.jar` 是二进制文件，无法在本环境生成。所以要么用 Android Studio（它会自动补上），
要么在项目根目录执行一次 `gradle wrapper`（需要本机已有 Gradle 8.7）。

## 一、申请的权限（以及为什么）

全部权限都在 `app/src/main/AndroidManifest.xml` 里，逐条说明：

| 权限 | 必要性 | 用途 |
|---|---|---|
| `INTERNET` | **必需** | 局域网 TCP 对战连接 + UDP 房间广播发现 |
| `ACCESS_NETWORK_STATE` | 必需 | 判断网络是否可用、断线提示 |
| `ACCESS_WIFI_STATE` | 必需 | 读取本机 WiFi 网段，界面上显示「我的 IP」给朋友输入 |
| `VIBRATE` | 可选 | 出牌/炸弹震动反馈 |
| `POST_NOTIFICATIONS` | 可选（Android 13+ 运行时申请） | 「轮到你出牌」后台提醒；**拒绝也不影响对战** |

**刻意不申请的权限**（标准斗地主不需要，申请了只会让用户警惕）：

- 定位（GPS / 网络定位）
- 相机、麦克风
- 通讯录、短信、通话记录
- 电话状态（**不拿 IMEI 当设备号**，改用首次启动生成的随机 UUID 存在本地）
- 外部存储读写（贴图全部打包进 APK 的 assets，不写手机存储）
- `QUERY_ALL_PACKAGES`
- `FOREGROUND_SERVICE`（不做后台常驻，退到后台就断线，不做隐蔽的常驻服务）

另外 `android:allowBackup="false"` + 禁用了云备份/设备迁移，避免把本地存档和设备 ID 带走。

**网络安全配置**：本游戏只在局域网内用明文 TCP/UDP，不访问任何互联网服务器，因此
**不需要** `usesCleartextTraffic` 或 `network_security_config.xml`（没有任何 HTTP 请求）。
如果你以后把服务器搬到公网，请改成 `wss://`，不要放宽明文策略。

## 三、怎么联机玩

1. **同一 WiFi**（手机热点也行）。
2. 玩家 A 打开游戏 → 点**「创建房间（我当房主）」**。
3. A 的屏幕上会显示 **`192.168.x.x : 9527`**，把这个告诉 B 和 C。
4. B / C 打开游戏 → 左侧**「附近的房间」**里点一下就能加入（UDP 广播自动发现）；
   如果列表是空的（部分路由器/企业 WiFi 会屏蔽广播），点**「手动输入房主 IP」**填 A 的 IP → 「连接」。
5. 三人到齐后各自点**「准备」**，自动开局。
6. **人不够也能玩**：房主点**「开始游戏（电脑补齐）」**，空位由 AI 接管。

**房主也可以中途掉线**：其他玩家不会卡死，房主的座位会由 AI 接管，牌局继续打完。

### 防火墙提示

Windows 上第一次当房主时，系统会弹「是否允许斗地主访问网络」——**必须勾选「专用网络」并允许**，
否则别人连不进来。端口是 **9527（TCP 对战）** 和 **9528（UDP 房间发现）**。

### 跨网络（不推荐，需要端口映射）

房主需要在路由器上把 9527/TCP 映射到本机，其他人填公网 IP。手机流量玩家无法做端口映射，
所以**本方案定位就是局域网**。如果需要公网联机，请告诉我，我可以再加一个公网服务器模式。

## 五、关键设计（为什么这么做）

**1. 房主权威，客户端零信任**

房主持有全部三家手牌、决定发牌、校验每一手牌是否合法。客户端发来的每一手牌都要过三道校验：
`Rules.contains`（手牌里真的有这些牌）→ `ComboParser.parse`（是合法牌型）→ `Rules.canBeat`（压得过上家）。
消息绑定到「该 TCP 连接自己的座位号」，而不是消息里自称的座位，所以**改客户端无法作弊**，
最多把自己弄成非法操作被拒绝。手牌只发给本人，抓包也看不到别人的牌。

**2. 单线程状态机，彻底消灭竞态**

所有网络回调（后台线程）只做一件事：把闭包丢进 `ConcurrentLinkedQueue`；渲染线程每帧 `drain()` 执行。
房主自己的操作同步直达会话（本来就在渲染线程上）。因此 `HostSession` **只在单个线程上被触碰，
内部没有任何锁** —— 这是这类游戏最容易出错也最难调试的地方，用架构直接回避。

**3. 超时即托管，牌局永不卡死**

每个决策点都有 deadline（叫分 10s / 出牌 20s），超时由 `tick()` 强制推进；玩家掉线后 AI 接管。
`AiPlayer` 只在 `Rules.enumerateAll` 产出的合法牌型里挑，所以**永远不会产生非法操作**，
也永远能给出一个决定（出牌或过）。

**4. 手牌中心左移，给右侧竖排按钮让位**

横屏 1280×720 虚拟坐标下，20 张手牌最宽 870px，右侧 1180px 处竖排三个按钮，永不重叠。

## 六、玩法规则（本实现采用的口径）

- **叫分**：一轮叫分制。随机一人先叫，三人各一次机会，每次必须高于当前最高分（或弃叫）；
  叫 3 分立即成为地主；三家全弃则**重新发牌**。底分 = 最终叫分。
- **牌型**：单张、对子、三张、三带一、三带二、顺子（≥5 张）、连对（≥3 对）、
  飞机（≥2 个连续三张）、飞机带单、飞机带对、四带二（4+2）、四带两对（4+2 对）、炸弹、王炸。
  顺子/连对/飞机的连续部分**不能含 2 和大小王**（A 可以，如 `10 J Q K A`）。
- **比大小**：同型同长比点数；炸弹压普通牌型；炸弹之间比点数；王炸最大。
- **倍数**：每个炸弹/王炸 ×2；春天（地主赢且两农民一张没出）×2；反春（农民赢且地主只出了一手）×2。
  总倍数 1024 封顶。
- **结算**：地主赢 = 底分 × 倍数 × 2，每个农民扣 底分 × 倍数；地主输则相反。

## 七、已知限制 / 尚未验证的地方

1. **未编译、未运行、未联机实测过。** 全部正确性来自静态审查与逐行推理。第一次构建若报错，
   把报错原文发我，我来定位。
2. AI 是启发式的（先跟牌、再控场、农民不互相压制），**不是强力 AI**，够朋友局用。
3. 局域网模式依赖 UDP 广播能被路由器转发；广播被屏蔽时用**手动输入 IP**（永远可用）。
4. 手机作为房主时最多 2 名其他玩家（三人局）；不支持观战、不支持 4 人以上。
5. 断线重连依赖本地持久化的 `clientId`；如果玩家**清除应用数据**，重连会被当成新玩家。
6. 计分只是内存里的累计分，**退出应用即丢失**，没有做排行榜或持久化战绩。
7. 没有做断线时的「离线出牌队列」，断线期间的操作不会补发（重连后拿服务端快照）。
8. **房主向某个卡死的连接写消息是在渲染线程上同步进行的。** 消息都很小（最大约 400 字节），
   局域网下内核发送缓冲能立刻吸收，实践上不会卡；但如果某个客户端长时间不读数据把发送缓冲写满，
   房主的画面可能出现短暂卡顿。要做严格隔离的话，应给每个连接加一个发送队列 + 写线程。
9. 断线重连后不会自动回到牌局，需要玩家重新输入房主 IP 加入（座位与手牌会被正确地复用）。
